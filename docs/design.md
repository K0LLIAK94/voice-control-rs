# Voice Control: решение по реализации

Дата: 24 октября 2026, Europe/Moscow. Режим `/office-hours`: Builder.
Статус: рабочее решение, принято агентом по прямому поручению пользователя принимать решения самостоятельно. Это не запись об отдельном пользовательском утверждении документа.

## Задача и исходные данные

Пользователь передал `Laitis.exe` и прямо уточнил, что требуется зареверсить именно этот файл. Затем требуется собственная реализация на Rust с исходным кодом, приватным GitHub-репозиторием и двумя ежедневными сценариями: голосовое управление воспроизведением и микрофоном Discord.

В приложенном изображении показана системная медиапанель Windows 11 с источником Google Chrome и фильмом «Энн (2017)». Поэтому «встроенный плеер» понимается как текущая медиасессия Windows. Создание ещё одного проигрывателя не решает показанный сценарий.

До начала работы папка содержала только `Laitis.exe`, без исходников, Git-истории и проектных инструкций. Технические утверждения о Laitis допускаются только после анализа этого файла через REA; название продукта само по себе не доказывает способ захвата или распознавания звука.

## Решение и проверенные предпосылки

- Использовать Rust для собственного приложения, а Windows API для системных действий. Исходный `Laitis.exe` остаётся материалом анализа и не входит в поставку нового приложения.
- Изучить через REA код пути «микрофон → подготовка аудио → распознавание → команды». Сохранить локальные Evidence и отчёт с методами, параметрами и ограничениями. Не называть чтение обычными shell-инструментами результатом REA.
- Переносить подтверждённые алгоритмы и поведение в новую реализацию. Не переносить чужие ключи, серверные токены, закрытые DLL, брендинг или бинарник в открываемые исходники.
- Начать с приватного репозитория, как запрошено. Собственные исходники получают открытое лицензирование; приватность репозитория и лицензия кода являются разными решениями. Публичная публикация сейчас не запрошена.
- Не требовать платную учётную запись распознавания для основных четырёх команд. Окончательный выбор доступного движка фиксируется по результатам анализа и проверки среды, а различия с Laitis раскрываются в README.

## Альтернативы

| Подход | Что даёт | Цена и риск | Решение |
| --- | --- | --- | --- |
| Минимальный: консоль Rust с захватом микрофона и двумя действиями | Самый короткий путь проверки полного голосового цикла | Неудобно пользоваться постоянно; недостаточно видимости состояния | Использовать как диагностический режим, не считать всей поставкой |
| Основной: Rust-приложение в трее, проверенный аудиопуть, узкий словарь команд и отдельные адаптеры Windows | Полезная ежедневная программа, понятные ошибки, возможность сменить распознаватель | Нужно проверять реальные устройства, медиасессии и Discord отдельно | Выбран |
| Полная реплика всего Laitis, включая каждую интеграцию и редактор сценариев | Наибольший потенциальный охват | Передан только один артефакт; состав функций, сервисов и внешних зависимостей ещё не установлен | Сначала составить инвентарь REA. Не заявлять полную эквивалентность без проверки каждой функции |

Выбор основного подхода не означает, что исследование Laitis можно заменить готовой сторонней голосовой утилитой. Реверс переданного файла является отдельным обязательным результатом. «Копия Laitis» не считается доказанной только потому, что четыре команды срабатывают: отчёт должен отдельно назвать воспроизведённые механизмы, отличия и непроверенные функции.

## Поведение пользователя

| Произнесено | Требуемый результат |
| --- | --- |
| `играй` | Запустить текущую доступную медиасессию Windows |
| `пауза` | Приостановить текущую доступную медиасессию Windows |
| `мут` | Выполнить привязанное в Discord действие через Insert |
| `размут` | Выполнить привязанное в Discord действие через Insert |

Медиакоманды должны задавать желаемое состояние, когда медиасессия предоставляет такую возможность. Повторное `пауза` не должно запускать фильм. Отсутствующая медиасессия показывает понятный статус и не считается успешным действием.

Insert в Discord является пользовательской привязкой, а не сообщением о фактическом состоянии микрофона. Одна симуляция клавиши сама по себе не доказывает, что Discord стал muted/unmuted. Приложение должно явно различать команду-переключатель и подтверждённое состояние. Запрещено показывать фиктивное «микрофон выключен», если известна только отправка Insert. Если используется локальная оценка состояния, нужен видимый способ синхронизировать её после ручного переключения и перезапуска; это ограничение раскрывается пользователю. Изолированно проверяется отправка пары key-down/key-up и фактическая реакция Discord.

Распознаётся законченная фраза из настроенного набора, с нормализацией регистра, пробелов и пунктуации. Поиск подстроки `мут` внутри `размут` недопустим. Частичные результаты распознавания и повторные уведомления одного высказывания не должны повторять действия. Неизвестная фраза не вызывает действие. Псевдонимы и время защиты от дублей доступны в настройках.

## Устройство приложения

```text
микрофон
    ↓
захват / преобразование / детектор речи
    ↓
распознаватель
    ↓
законченная фраза → нормализация → точное сопоставление → защита от дублей
    ↓
команда
    ├── медиасессии Windows: Play / Pause
    └── Discord: настроенная клавиша Insert
```

Путь аудио реализуется на основании конкретных результатов REA, а не предположения, что у Laitis есть собственная нейросеть. Если обнаружится облачный распознаватель, отдельно фиксируются аудиоформат, буферизация и граница внешнего сервиса. Собственная реализация захвата и подготовки аудио может сохранять это поведение при открытом доступном движке распознавания; такая замена называется явно.

Захват, распознавание, маршрутизация команд и Windows-действия разделены. Аудиопоток не должен блокироваться на медиакомандах или GUI. Очереди ограничены, ошибки устройства и остановка обрабатываются. Потеря микрофона не отображается как «слушаю». Пауза прослушивания прекращает распознавание; выход освобождает устройство.

## Интерфейс и настройки

Основной интерфейс: системный трей со статусом прослушивания, командой приостановить/возобновить, доступом к настройкам, диагностике и выходу. Названия действий на русском. Статус различает «слушаю», «приостановлено» и ошибку устройства/модели. Настройки включают устройство ввода, путь к модели и произносимые команды. Клавиша Discord фиксирована как Insert по прямому запросу пользователя.

Поставляемый пример конфигурации пригоден для четырёх команд. Пользовательские настройки и модели не оказываются в Git. Программа не сохраняет сырые записи речи и распознанные разговоры по умолчанию. Диагностика имеет явный режим и ограниченное хранение. Автозапуск не изменяется скрыто: готовый бинарник запускается обычным действием пользователя, а добавление в автозагрузку доступно отдельно.

При необходимости выбора между несколькими плеерами используется текущая медиасессия Windows и настраиваемое предпочтение приложения. Нельзя случайно управлять другим плеером, показав успех для желаемого. Неудача Win32-ввода, отсутствие Discord и конфликт уровня привилегий должны отражаться в диагностике.

## Приёмка: что доказывает готовность

| Требование | Необходимое доказательство |
| --- | --- |
| Зареверсить именно переданный файл | SHA-256 и размер `Laitis.exe`, успешный запуск REA на этом пути, сохранённые Evidence и отчёт с происхождением выводов |
| Взять логику голоса из Laitis | Конкретные методы/вызовы и параметры из анализа сопоставлены с новым аудиопутём; каждое намеренное отличие указано |
| Rust и доступные исходники | Cargo-проект с исходниками, воспроизводимая сборка Windows, лицензия и README |
| Голос → действие | Запись/реальный микрофон проходит весь аудиопуть, фраза распознана, действие действительно выполнено; текстовый mock отдельно не доказывает это |
| Играй/пауза | Проверка с реальной текущей сессией (включая Chrome при наличии), повторы не меняют желаемое состояние |
| Мут/размут через Insert | Проверенная пара событий Insert и отдельное наблюдение реакции Discord; честный статус при недоступном подтверждении |
| Отсутствие ложных команд | Молчание, посторонняя фраза, `размут`, дубли partial/final, неизвестные слова и быстрые последовательности покрыты соответствующими тестами |
| Пользование каждый день | Трей работает, прослушивание ставится на паузу, ошибки видны, выход освобождает микрофон; конфиг валидируется |
| Приватный GitHub | Реально созданный репозиторий с `private=true`, отправленная история исходников и проверяемая ссылка |
| Поставка | Собранный исполняемый файл, конфигурация и инструкции по модели; Windows CI проверяет тесты и сборку |

Проверки маршрутизатора, синтетический ввод текста, replay WAV, живой микрофон и наблюдение внешнего приложения отмечаются разными видами доказательства. Неуспешная или недоступная проверка остаётся открытым пунктом, даже если соседние тесты зелёные.

## Распространение и последовательность работы

Приватный GitHub хранит собственные исходники, конфигурационный пример, отчёт с разрешёнными выводами анализа, тесты и сборочную инструкцию. Исходный Laitis, полная декомпиляция чужого продукта, скачанные модели, пользовательские записи и секреты исключены из коммитов. Windows GitHub Actions запускает проверки и сборку; готовый архив включает бинарник и минимальную инструкцию. Платные сервисы и публичная публикация для этого этапа не нужны.

1. Подтвердить идентичность Laitis и завершить REA-анализ голосового пути.
2. Реализовать этот путь в Rust и провести replay/диагностическую проверку захвата.
3. Подключить реальные медиадействия и Insert, проверить ошибки и повторы.
4. Добавить трей, настройки и пригодную для запуска поставку.
5. Проверить полный голосовой цикл, исходники и приватный репозиторий по таблице приёмки.

## Следующее реальное действие

После запуска готовой сборки проверить четыре команды своим голосом при открытом фильме в Chrome и работающем Discord, затем вручную нажать Insert и проверить, как приложение сообщает и восстанавливает известное состояние. Это проверяет именно пользовательскую среду, которую тесты маршрутизатора воспроизвести не могут. Пока пользователь отсутствует, агент выполняет все доступные проверки и сохраняет честные результаты.

## Наблюдения из запроса

- «при том как я говорю играй пауза» задаёт разговорный интерфейс без переключения окон, поэтому главное действие должно быть доступно из фонового приложения.
- «для этого использую insert» задаёт существующую привычку и интеграционную границу Discord; менять её без необходимости не следует.
- «логику взятия голоса бери из приложения Laitis» и последующее уточнение о реверсе требуют доказательств из артефакта, а не только совместимых названий команд.
- «ничего не спрашивай все решения принимай сам» задаёт автономный ход работы. Неопределённости фиксируются как принятые предположения и проверяются, а не превращаются в фиктивные ответы пользователя.
